# Deploy SonicJs Headless CMS to Cloudflare

You'd think deploying your code and database to over 200 global server nodes would be a headache, however its as simple as committing code to your main branch once its setup. {{ className: 'lead' }}

## Update your production database

```cmd
npm run up:prod
```

This will update your production database to be in sync with your latest [schema](/persistence#schema). Of course, if you haven't
made any schema updates, you can skip this step.

# Deploy (via the Cloudflare UI)

Deploying your SonicJs Headless CMS with the Cloudflare UI provides you with the ability to:
1. Setup multiple environments (ie: preview and production)
1. Setup automatic deployments so that your app is deployed on code commit
1. Setup [environment variables](/environment-variables) and binding
1. Setup custom domain name(s)
1. Manage who can access your Cloudflare deployment
1. Much more...

## Database Deployment

The first thing we'll want to do is upgrade our production database schema. To do this simply run the command:

```cmd
npm run up:prod
```

That should be all you need to do, but if you run into issues or want more details, please see the full [migrations](/persistence#migrations) section. Note that 
you can skip this steps if you haven't made any [schema](/persistence#schema) updates.

## Code Deployment
1. Login in to Cloudflare [https://dash.cloudflare.com/](https://dash.cloudflare.com/). You can register for an account for free if you don't already have one.
1. Select "Workers & Pages" from the left hand navigation.
1. Click "Create application"
1. Click the "Pages" tab
1. Click "Connect to Git"
1. Select your SonicJs repo from the list, then "Begin setup"
1. Enter the following details
   * Framework present - leave as "None"
   * Build command - "npm run build" without the quotes
   * Build out directory - "dist"  without the quotes
1. Click "Save and Deploy"

At this point, Cloudflare will build and deploy your application. However you'll get an error if you visit the provided URL since we haven't setup bindings
for our KV and D1 data stores. To do that:

1. From you app's main page, navigate to Settings -> Functions
1. In the KV namespace bindings sections, click "Add binding"
   1. Variable Name: KVDATA
   1. KV namespace: [select the KV namespace that you want to use]
      * If you don't already have a production KV namespace run the command `wrangler kv:namespace create sonicjs` 
1. In the D1 database bindings section, click "Add binding"
   1. Variable Name: D1DATA
   1. D1 database: [select the D1 database that you want to use]
      * If you don't already have a production D1 database run the command `wrangler d1 create sonicjs` 
1. (Optional if you want to manage files) In the R2 bucket bindings section, click "Add binding"
   1. Variable Name: R2STORAGE
   1. R2 bucket: [select the R2 bucket that you want to use]
      * If you don't already have a production R2 database run the command `wrangler r2 bucket create sonicjs` 
1. Redeploy SonicJs so that it has access to your newly created variables.
   1. Navigate to your app's main page.
   1. From the Deployments tab, you should see an "All Deployments" section
   1. Click the "..." menu at the end of the latest deployment and click "Retry Deployment"
   1. Wait for the deployment to succeed which should take about a minute or so.


Now you should be able to head back over to the browser were your app's url is loaded and refresh the page.

if you see any errors, be sure to check the `/status` url on your deployed app. If all is working you should see
