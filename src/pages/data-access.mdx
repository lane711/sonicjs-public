# Data Accessing

Once you have defined your [data schema](/persistance#schema) and [routing](/routing), you'll want to be able to manage your data.

With SonicJs you can use the built in data access tier or interact directly with the 3 layers of data persistance:
1. [Cache (In-Memory)](/persistance#caching-in-memory-and-kv-cache)
1. [KV (Key-Value pair store)](/persistance#caching-in-memory-and-kv-cache)
1. [D1 (A SQLite SQL database)](/persistance#accessing-d1-sql-data)

It is recommend that you use the built in data-tier in order to get the benefits of caching, however this may not be suitable for all use-cases.

Here is a basic example below. This file is also loctied in the repo here:

`src/custom/example.ts`

```ts
import { Hono } from "hono";
import qs from "qs";
import { getData } from "../cms/data/data";

const example = new Hono();

example.get("/", (ctx) => {
  return c.text("Hello SonicJs!");
});

example.get("/users", async (ctx) => {
    var params = qs.parse(ctx.req.query());
    const data = await getData(ctx.env.D1DATA, ctx.env.KVDATA, 'users', params,ctx.req.url, 'fastest' );
    return ctx.json(data);
  });

export { example };
  ```

  Note: you will need to prefix your example route with `v1` because of how its setup in `src/server.ts`, so to access your users example:

  `http://localhost:8788/v1/example/users`
